# 第三阶段：来源注册与授权管理

日期：2026-10-30（北京时间）

本阶段在用户确认初始化验收后执行，完成来源管理基础设施，不进入真实官网采集或校园账号接入。

## 完成内容

- 登记八类目标来源：西电学校官网、计算机科学与技术学院官网、学校公众号、学校微信企业号、QQ 群、微信群、学在西电、XDYou。
- 默认未申请授权、禁用；不预置已授权状态、校园通知、账号或未知 API 地址。
- 授权范围、依据、有效期、操作者确认和修改原因管理。
- 来源设置的乐观版本校验；不可改写的授权 / 设置变更记录。
- 手工接入单独启用，未授权、到期、撤销或未实现的接入方式不能导入登记来源消息。
- 原文与来源 ID 关联，保存录入时授权快照，历史追溯不受之后撤销影响。
- 管理界面显示真实状态，录入框只允许选择有效启用的登记来源。
- 浏览器体验版使用同样的状态规则，旧 IndexedDB 消息保留，首次访问时添加默认来源登记。
- Alembic 版本化迁移、旧 SQLite 结构校验、升级前 SQLite 备份；新增 migrate / migrate-check 命令。
- SQLite / PostgreSQL / 前端与双构建的最小 GitHub Actions 工作流。

## 授权与接入的边界

“已登记授权”是操作者提供依据并主动确认后的本地记录，不是系统代替学校核实授权。公开网页接入同样需要确认范围及依据；本阶段不读取网站。

当前仅实现主动手工录入。public_web 是待开发接入方式，不可启用；没有虚构学校企业号、学在西电、XDYou 或聊天平台的接口，也没有 Canvas 或 DeepSeek 依赖。

来源注册目前为八类固定目标，授权范围中应明确允许处理的具体栏目、公众号或群及用途；多账号 / 多群的独立来源实例管理未在此阶段实现。

## 数据库升级

迁移历史：

- `0001_initial` 固定第一阶段四张表的结构，用于新库初始化及旧库基线校验。
- `0002_sources` 增加 sources / source_events，以及 messages 的可空 source_id / authorization_snapshot，旧记录不回填伪造授权。

已有 SQLite 已先备份并升级到 `0002_sources`。四张旧表升级前后记录数一致，完整性检查 ok，foreign_key_check 无错误。应用启动只初始化空库；已有未升级库会提示执行迁移，不静默修改已有结构。未知 / 部分结构在写入版本前被拒绝。
